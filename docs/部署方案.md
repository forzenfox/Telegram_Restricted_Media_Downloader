# TRMD Docker 部署方案

## 1. 概述

本文档描述 TRMD（Telegram Restricted Media Downloader）的 Docker 生产部署方案。

### 部署原则

- 镜像由 CI 流水线构建并推送至 `ghcr.io`，**生产环境不直接构建镜像**
- 数据与代码分离，所有持久化数据位于 `deploy/` 目录下
- 通过一键脚本完成部署、重启、清理操作

---

## 2. 目录结构

```
TRMD/
├── deploy/                          # 部署目录，与项目代码分离
│   ├── .env                         # 部署参数（镜像标签、端口号等）
│   ├── docker-compose.yml           # 服务编排
│   ├── config/
│   │   └── config.yaml              # 应用配置（用户填写，只读挂载）
│   ├── data/
│   │   └── .trmd/                   # 数据库及运行时数据（trmd.db + interaction_state.json）
│   ├── logs/                        # 日志目录（trmd.log + 备份 trmd_*.log）
│   ├── sessions/                    # Telegram 会话文件
│   ├── downloads/                   # 下载文件
│   ├── temp/                        # 临时文件（下载过程中）
│   ├── form/                        # 表单数据
│   ├── deploy.sh                    # 一键部署
│   ├── restart.sh                   # 一键重启
│   └── cleanup.sh                   # 一键清理
├── docs/                            # 项目文档
├── module/                          # 项目代码
├── Dockerfile                       # 运行时镜像构建文件
├── Dockerfile.base                  # 基础镜像构建文件
└── docker-compose.yml               # 本地开发用 compose
```

> **说明**：`deploy/` 下的目录在首次部署时自动创建，无需手动 mkdir。

## 3. 镜像管理

### 3.1 镜像仓库

| 镜像 | 推送位置 | 用途 |
|------|----------|------|
| `ghcr.io/forzenfox/trmd-base:latest` | CI 流水线 base job | 构建缓存层，间接依赖 |
| `ghcr.io/forzenfox/trmd:<tag>` | CI 流水线 build job | 运行时镜像，部署直接使用 |
| `ghcr.io/forzenfox/trmd:latest` | CI 流水线 build job | 最新稳定版 |

### 3.2 镜像标签策略

- git tag 触发：`v1.2.3` → 镜像 tag `1.2.3` + `latest`
- 手动触发：可指定任意 tag

### 3.3 更新策略

部署和重启脚本均先拉取最新镜像再启动容器，确保每次部署使用最新版本。

## 4. 配置文件

### 4.1 `.env` — 部署参数

```env
# 镜像配置
IMAGE_NAME=ghcr.io/forzenfox/trmd
IMAGE_TAG=latest

# 端口映射
HOST_PORT=8000

# WebUI 访问地址（部署到服务器时改为实际域名）
# 留空则使用 config.yaml 中的 webui.base_url
TRMD_WEBUI_URL=

# 时区
TZ=Asia/Shanghai

# 容器名
CONTAINER_NAME=trmd
```

### 4.2 `config/config.yaml` — 应用配置

从项目根目录 `config.example.yaml` 复制并填写实际配置（api_id、api_hash、bot_token 等）。

> 首次部署前必须完成此文件的配置，否则容器启动后将无法正常运行。

## 5. 服务编排（docker-compose.yml）

```yaml
services:
  trmd:
    image: ${IMAGE_NAME}:${IMAGE_TAG}
    container_name: ${CONTAINER_NAME}
    restart: unless-stopped
    stdin_open: true
    tty: true
    ports:
      - "${HOST_PORT}:8000"
    volumes:
      # 配置（只读挂载）
      - ./config/config.yaml:/app/config.yaml:ro
      # 数据库及运行时数据
      - ./data/.trmd:/app/.trmd
      # 日志（目录挂载，自动持久化日志与轮转/备份文件）
      - ./logs:/app/logs
      # 数据目录
      - ./sessions:/app/sessions
      - ./downloads:/app/downloads
      - ./temp:/app/temp
      - ./form:/app/form
    environment:
      - TZ=${TZ}
```

### 挂载点说明

| 容器内路径 | 宿主机路径 | 读写 | 用途 |
|-----------|-----------|------|------|
| `/app/config.yaml` | `deploy/config/config.yaml` | `ro` | 应用配置文件 |
| `/app/.trmd` | `deploy/data/.trmd` | `rw` | SQLite 数据库 (trmd.db) + 运行时状态 |
| `/app/logs` | `deploy/logs/` | `rw` | 日志目录（目录挂载，含 trmd.log 与轮转/备份文件） |
| `/app/sessions` | `deploy/sessions/` | `rw` | Telegram 会话文件 |
| `/app/downloads` | `deploy/downloads/` | `rw` | 已下载文件 |
| `/app/temp` | `deploy/temp/` | `rw` | 下载过程中的临时文件 |
| `/app/form` | `deploy/form/` | `rw` | 表单数据 |

> **日志挂载说明**：日志写入容器内 `/app/logs/trmd.log`（项目根 `/app`），使用目录挂载 `./logs:/app/logs` 持久化。目录挂载下，应用启动时对日志文件的备份/重命名与 `RotatingFileHandler` 轮转都发生在宿主机 `logs/` 目录内，备份（`trmd_*.log`）与活跃日志均可见，`docker compose down` 不会丢失。应用会自动创建日志目录，`deploy.sh` 和 `restart.sh` 仅需 `mkdir -p logs`。

## 6. 服务器初始化操作

以下操作在云服务器上首次部署时执行，**仅需执行一次**。

### 6.1 安装依赖

```bash
# Docker（Ubuntu/Debian）
curl -fsSL https://get.docker.com | sh
sudo usermod -aG docker $USER
# 退出当前 SSH 会话后重新登录，或执行 newgrp docker 立即生效

# Docker Compose（如未随 Docker 安装）
sudo apt install docker-compose-plugin

# 验证
docker --version
docker compose version
```

### 6.2 创建部署目录

```bash
mkdir -p /opt/trmd_plus
cd /opt/trmd_plus
```

### 6.3 获取部署文件

> 使用 `curl` 从 GitHub 下载所需文件，避免 clone 整个仓库。

```bash
cd /opt/trmd_plus

# 下载部署脚本
curl -fsSL https://raw.githubusercontent.com/forzenfox/TRMD/main/deploy/deploy.sh -o deploy/deploy.sh
curl -fsSL https://raw.githubusercontent.com/forzenfox/TRMD/main/deploy/restart.sh -o deploy/restart.sh
curl -fsSL https://raw.githubusercontent.com/forzenfox/TRMD/main/deploy/cleanup.sh -o deploy/cleanup.sh

# 下载 docker-compose 编排文件
curl -fsSL https://raw.githubusercontent.com/forzenfox/TRMD/main/deploy/docker-compose.yml -o deploy/docker-compose.yml

# 下载 .env 模板
curl -fsSL https://raw.githubusercontent.com/forzenfox/TRMD/main/deploy/.env.example -o deploy/.env.example

# 下载应用配置模板（放在 deploy/config/ 下，便于后续编辑）
curl -fsSL https://raw.githubusercontent.com/forzenfox/TRMD/main/config.example.yaml -o deploy/config/config.yaml.template

# 赋予脚本执行权限
chmod +x deploy/deploy.sh deploy/restart.sh deploy/cleanup.sh
```

### 6.4 创建预置目录结构

```bash
cd /opt/trmd_plus/deploy
mkdir -p config data/.trmd logs sessions downloads temp form

# 创建日志目录（Docker 目录挂载 ./logs:/app/logs）
mkdir -p logs
```

### 6.5 初始化配置文件

```bash
cd /opt/trmd_plus/deploy

# 从下载的模板创建应用配置
cp config/config.yaml.template config/config.yaml

# 编辑配置，填入 Telegram API 凭证
vim config/config.yaml
# 必填项：credential.api_id、credential.api_hash、credential.bot_token（可选）
```

### 6.6 配置部署参数

```bash
# 创建 .env 文件
cat > .env << 'EOF'
# 镜像配置（将 forzenfox 替换为你的 GitHub 用户名）
IMAGE_NAME=ghcr.io/forzenfox/trmd
IMAGE_TAG=latest

# 端口映射（宿主机端口:容器端口，默认 8000）
HOST_PORT=8000

# WebUI 访问地址（部署到服务器时必须改为实际域名，如 https://trmd.example.com）
TRMD_WEBUI_URL=

# 时区
TZ=Asia/Shanghai

# 容器名
CONTAINER_NAME=trmd
EOF
```

### 6.7 首次部署验证

```bash
# 检查目录结构是否完整
ls -la
# 应包含：config/ data/ logs/ sessions/ downloads/ temp/ form/ .env

# 确认配置文件已填写
cat config/config.yaml | grep -E "api_id|api_hash"

# 执行部署
./deploy.sh
```

## 7. 首次登录（Telegram 客户端认证）

### 7.1 登录流程说明

项目启动时需要完成 **Telegram 客户端登录**，这是一个交互式过程：

1. **输入电话号码**：需带国际区号（如 `+861500000000`）
2. **确认号码**：输入 `y` 确认
3. **输入验证码**：通过 SMS/Telegram App/电话发送
4. **两步验证**（可选）：如账号开启了两步验证，需输入密码

登录成功后，Pyrogram 将 session 文件保存到 `sessions/` 目录，后续启动自动复用，**无需再次登录**。

### 7.2 首次部署登录步骤

首次部署时，`deploy.sh` 会自动检测是否需要登录，并引导用户完成交互式登录：

```bash
cd /opt/trmd_plus/deploy
./deploy.sh
```

脚本执行流程：
1. 拉取镜像并启动容器（前台模式）
2. 检测到 `sessions/` 目录为空，提示用户进行 Telegram 登录
3. 用户在容器内输入手机号、验证码完成登录
4. 登录成功后，按 `Ctrl+C` 退出容器
5. 脚本自动重启容器为后台模式

### 7.3 手动登录（如自动检测失败）

如果自动检测未触发登录流程，可手动执行：

```bash
cd /opt/trmd_plus/deploy

# 停止后台容器
docker compose down

# 以前台交互模式启动（用于登录）
docker compose run --rm trmd

# 登录完成后，按 Ctrl+C 退出
# 然后重新启动为后台模式
docker compose up -d
```

### 7.4 登录状态检查

```bash
# 查看 sessions 目录是否有文件
ls -la sessions/

# 查看容器日志，确认登录状态
docker compose logs | grep -i "login\|authorized\|session"
```

## 8. 一键部署脚本（deploy.sh）

### 执行流程

```
1. 前置检查
   ├── 检查 Docker 是否安装
   ├── 检查 Docker Compose 是否安装
   └── 检查 config/config.yaml 是否存在

2. 创建日志目录
   └── mkdir -p logs（Docker 目录挂载 ./logs:/app/logs）

3. 停止旧容器
   ├── docker compose down（保留数据卷）
   └── 忽略"服务未定义"等错误

4. 拉取最新镜像
   └── docker compose pull

5. 启动新容器
   ├── docker compose up -d
   └── 等待 3 秒后检查容器状态

6. 验证部署
   ├── 显示容器运行状态
   └── 提示查看日志命令
```

### 使用方式

```bash
# 部署 latest 版本（.env 默认）
cd deploy
./deploy.sh

# 部署指定版本
IMAGE_TAG=v1.2.3 ./deploy.sh
```

## 10. 一键清理脚本（cleanup.sh）

### 清理策略

| 项目 | 默认行为 | 说明 |
|------|---------|------|
| 容器实例 | **清理** | `docker compose down` 停止并移除容器 |
| `temp/` | **清理** | 下载临时文件，可安全删除 |
| `form/` | **清理** | 表单数据 |
| `logs/` | **清理** | 日志文件 |
| `sessions/` | **保留** | Telegram 会话，删除后需重新登录 |
| `downloads/` | **保留** | 已下载文件 |
| `data/.trmd/` | **保留** | 数据库文件，包含任务记录、缓存、配置状态 |

### 可选参数

| 参数 | 效果 |
|------|------|
| `--purge-data` | 同时清理 `data/.trmd/`（数据库） |
| `--purge-all` | 清理所有数据（含 sessions、downloads、数据库） |

### 使用方式

```bash
cd deploy

# 默认清理（保留 sessions、downloads、数据库）
./cleanup.sh

# 清理所有数据
./cleanup.sh --purge-data

# 清理所有数据（含 sessions、downloads）
./cleanup.sh --purge-all
```

## 12. 数据持久化说明

### 必须保留的数据

| 数据 | 位置 | 说明 |
|------|------|------|
| Telegram 会话 | `deploy/sessions/` | 登录凭证，删除后需重新扫码/输入验证码 |
| 数据库 | `deploy/data/.trmd/trmd.db` | 任务记录、缓存、仓库索引等全部运行时数据 |
| 配置文件 | `deploy/config/config.yaml` | 应用配置 |

### 可安全清理的数据

| 数据 | 位置 | 说明 |
|------|------|------|
| 临时文件 | `deploy/temp/` | 下载中断后残留的 `.temp` 文件 |
| 表单数据 | `deploy/form/` | 临时表单缓存 |
| 日志目录 | `deploy/logs/` | 日志目录（trmd.log 默认上限 200MB，自动轮转，备份 `trmd_*.log`） |

## 14. 故障排查

### 容器启动后立即退出

```bash
# 查看容器日志
cd deploy && docker compose logs

# 常见原因：
# - config/config.yaml 未正确配置凭证
# - 数据目录权限不足
# - 端口被占用
```

### 数据库文件损坏

```bash
# 清理数据库（注意：会丢失所有任务记录）
cd deploy
./cleanup.sh --purge-data
./deploy.sh
```

### 需要重新登录 Telegram

```bash
# 删除会话文件后重启
cd deploy
rm -rf sessions/*
./restart.sh
```
